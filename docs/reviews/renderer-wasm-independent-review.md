## Findings

### MAJOR — valid PointValue and Nearest canonical scenes are rejected by the browser mirror

Source: `research/renderer/scene.js:266-276`, especially the object-only
`validateConfiguration` check. Rust/Serde emits unit enum methods as the JSON
strings `"PointValue"` and `"Nearest"`, while this code requires every method
to be a non-array object and therefore raises `type: configuration.method must
be a tagged object`. Both methods are explicitly admitted by
`validateMetricDefinition` at `scene.js:298-305` and by the Rust adapter.

There is a second order error in the same path: `expectedCell` at
`scene.js:466` returns an unknown cell for `PointValue` before its exact
coincident-group check at `scene.js:471`; Rust checks the exact observation
first (`crates/spatial-analysis/src/model.rs:240-256`). Thus accepting the
wire spelling alone would still reject a valid PointValue tile with observed
cells as a numerical mismatch.

Reproduction retained under
`/Users/vincent/code/kyberia/.worktrees/windows-analysis-requests/.trash/test-runs/renderer-review-1af1cba/`:

- `point-fixture/point-scene.json`: generated by a copy of the checked-in
  canonical-scene generator with `MetricDefinition::signal_rssi()` and
  `Method::PointValue`; generator output is 19,106 bytes and SHA-256
  `c33f9471dead1ee4d2f5011998f0d7cb5c3ed81882745c903bff834bc107ef38`.
- `nearest-fixture/nearest-scene.json`: generated with
  `signal_rssi_nearest()` and `Method::Nearest`; output is 19,356 bytes and
  SHA-256 `d6185a62a0d0c3e2ba18be188ae9d2d12752b757a506ad6b003fb7bbf18580c5`.
- `point-rust-admission.log`: checked-in WASM returns `rustStatus: 0` for the
  PointValue scene and reports `configuration.method: "PointValue"`.
- `nearest-admission.log`: checked-in WASM returns `rustStatus: 0` for the
  Nearest scene and the JS loader returns
  `SceneLoadError(state=invalid, code=type, message=configuration.method must
  be a tagged object)`.
- `point-js-replay.log`: same JS error for PointValue.

Fix the JS wire-shape handling to match the Rust enum and move the exact
coincident check before the PointValue early return. Add browser/Node fixtures
for all three admitted metric identities, including an observed PointValue
cell and a non-observed Nearest cell.

### MAJOR — the exported loader can bypass the Rust admission authority

Source: `research/renderer/scene.js:649-655`:
`loadCanonicalScene` accepts an optional `canonicalValidator` and calls it only
when truthy. The production call at `research/renderer/renderer.js:693` passes
`validateCanonicalSceneWithWasm`, so the current UI route uses the intended
order. The exported loader and the existing direct tests omit the validator,
which silently restores the prior JS-only authority for any future caller.

Reproduction in `js-bypass.log`: calling `loadCanonicalScene` without options
accepts the escaped-schema bytes (SHA-256
`f2c149fa91a04c766f2d460259b4dc8abe9887308ef021825e3d7197305d5206`) and
float-width bytes (SHA-256
`dc863578f9774862f4652462ecb3811be8f451bebf8586f1930bc76db2660485`). The
Rust admission regression in `scene.test.mjs:71-78` independently returns
status 6 for escaped schema and a nonzero status for float width.

Make the Rust validator mandatory for the canonical loader, or split an
explicit test-only/diagnostic mirror from the production canonical loader so
omission cannot weaken the contract. Keep tests that exercise the mirror under
a separately named function and add a production-path test proving omission
fails closed.

### MAJOR — the worker request has no automatic deadline or fetch abort

Sources: `research/renderer/scene-validator-worker.js:9-12` and
`research/renderer/scene.js:570-606`. The worker fetches the checked-in module
with `{cache: 'no-store'}` but no `AbortController` or timeout. The caller's
only timer is a 20 ms polling `setInterval` that checks the optional
`isCancelled` callback; there is no deadline when that callback is absent, and
no deadline for a callback that never becomes true. A worker that never posts
an event, a fetch that stalls, or an expensive WASM validation therefore leaves
the returned Promise and worker alive indefinitely. The 64 MiB byte bound and
Rust's deterministic working-set estimate do not bound wall time or browser
linear-memory/RSS; the import path also holds multiple byte copies while the
worker allocates its input and validation state.

`worker-stall.log` uses a fake Worker that deliberately posts no response. At
100 ms the result is `{"observed":"still-pending","posted":1,"terminated":0}`.
The process was explicitly exited only to release the intentionally unresolved
review promise. User cancellation does terminate the worker in the tested
code path, but a resource/lifecycle boundary should not depend on a UI action.

Add a finite admission deadline, abort the worker-side fetch, terminate on
both deadline and cancellation, and surface a distinct resource/timeout state.
Test a stalled fetch, a silent worker, a WASM trap, cancellation while fetch is
pending, and cleanup after every terminal path. Consider a smaller browser
input budget or a documented memory policy that accounts for the main-thread
copies and WASM working set.
