7. **Bound/cancellation analysis.** The bridge caps input at 512 MiB, 2,000,000 blocks, 100,000 packets, 1 MiB per block, 32 sections, 256 interfaces per section, 120 seconds, 50,000 parsed frames, 50,000,000 aggregate parser work units and 256 MiB of conservative retained logical bytes (`src/lib.rs:34–44,48–59,83–117`). Caller limits cannot raise those ceilings. It preflights frame count, parser work/allocation budgets and staged-vector growth; it accounts for old plus planned capacity during growth and verifies actual vector capacity and growth peak before pushing the frame (`src/lib.rs:408–531`). The underlying parser meters per-frame work/allocation and validates explicit FCS framing while preserving the original MPDU bytes (`crates/ieee80211/src/lib.rs:73–78,914–935,1059–1066`). The importer independently bounds block/input/packet work and checks cancellation/deadline around reads (`crates/packet-import/src/pcapng.rs:35–77,241–319`). Staged results are private until the final complete-stream receipt, packet/disposition counts reconcile before publication, and any parse, import, resource or cancellation error returns no capture (`src/lib.rs:556–609`). The regression at `src/lib.rs:939–974` cancels only after one valid frame has been staged and asserts `Err(Cancelled)`, so it exercises the partial-staging failure case rather than an output cap.

   The exposed retained-byte measure is explicitly *logical* rather than a total-RSS guarantee; container input/block buffers are governed by their separate caps. `try_reserve_exact` actual capacity is checked after reservation, so allocator over-allocation could transiently exceed the planned logical vector budget before the call returns a resource-limit error. The request size remains bounded by `max_frames`; this is a residual peak-RSS caveat, not a demonstrated unbounded-input path. The docs should continue to avoid describing this as a total process-memory cap. Streaming reader calls may block despite the parser deadline; the implementation and architecture documentation correctly require process isolation for hard I/O timeouts.
